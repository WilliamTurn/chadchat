# Accessibility and inclusive design (canon 05)

Owning file: `docs/ux-canon/05-accessibility-inclusive.md` (146 principles). **[M]** mechanical (pass/fail checkable), **[J]** judgment. Cite numbers (e.g. `// canon 05 §70`). Automated scanners catch only ~30–40% (§137) — build these in, then do the manual passes (§20).

## Hard-rule digest

**1. Semantic HTML first** — 1 [M] use the native element that already means it (button/a/input/select/table/dialog). 2 [M] link=goes somewhere, button=does something. 3 [M] never click-handlers on non-interactive elements without full control semantics. 4 [M] DOM order matches visual/reading order (no CSS reordering). 5 [M] structure via markup (headings/lists/strong), not looks. 6 [M] data tables get real table markup + `<th scope>` + caption. 7 [M] declare page language + mark foreign passages. 8 [J] content survives CSS/pointer stripped away.

**2. Names, roles, values, ARIA** — 9 [M] every control exposes name+role+state. 10 [J] no ARIA beats bad ARIA. 11 [M] custom widget = full ARIA pattern, not just the role. 12 [M] accessible name contains the visible label text (voice control). 13 [M] never `aria-hidden` on focusable/interactive content. 14 [M] icon-only buttons get a text name. 15 [M] repeated controls get distinguishing names ("Edit Monday workout"). 16 [M] visual status is also programmatic (`aria-current`/`aria-selected`).

**3. Page structure** — 17 [M] one `<main>` + header/nav/footer landmarks, labeled duplicates. 18 [M] logical heading outline, one h1, no skipped levels. 19 [J] headings/labels describe topic/purpose. 20 [M] unique descriptive page title, updated on SPA route change. 21 [M] "skip to main content" first focusable. 22 [M] more than one way to find any page. 23 [J] link text makes sense out of context. 24 [M] iframes get `title`.

**4. Images & non-text** — 25 [J] informative images get purpose-conveying alt. 26 [M] decorative images `alt=""` (never missing). 27 [M] functional images named by action ("Search"). 28 [M] never real text inside images. 29 [M] complex images get a full text alternative nearby. 30 [M] alt doesn't start "image of" or duplicate captions. 31 [M] meaning-carrying icons get text; icons next to text get hidden. 32 [M] CAPTCHAs get non-visual alternatives — or don't exist.

**5. Dynamic updates / live regions** — 33 [M] content that changes without a page load announces itself (`role="status"`/`aria-live` or move focus). 34 [J] polite for status, assertive only for urgent. 35 [M] live regions exist in the DOM before you populate them. 36 [M] loading + completion are announced. 37 [J] don't announce noise (throttle/summarize). 38 [M] SPA route changes need explicit focus/announcement handling.

**6. Keyboard-only** — 39 [M] everything a mouse does, the keyboard does. 40 [M] no keyboard traps. 41 [M] tab order = visual/logical order (no positive tabindex). 42 [M] only interactive elements tabbable; everything interactive tabbable. 43 [M] standard key contract (Tab between, arrows within, Enter/Space activate, Esc dismiss). 44 [M] single-char shortcuts avoidable (WCAG 2.1.4). 45 [M] hover-revealed content is keyboard-reachable + dismissible (WCAG 1.4.13). 46 [M] custom scroll areas/carousels keyboard-operable. 47 [J] never intercept native keyboard behavior without full replacement.

**7. Focus** — 48 [M] visible focus indicator (≥2px, 3:1), never `outline:none` alone. 49 [M] focused element never fully hidden behind sticky UI (2.4.11, new in 2.2). 50 [M] dialog moves focus in on open, returns to trigger on close, traps while open. 51 [M] deleting the focused element places focus sensibly (not `<body>`). 52 [M] focus never moves without the user causing it. 53 [J] manage focus + reading position deliberately after in-page actions. 54 [J] don't blur/auto-dismiss in ways that destroy work.

**8. Low vision: zoom/reflow/resize** — 55 [M] works at 400% zoom, one column, no horizontal scroll (1.4.10). 56 [M] text scales to 200% without loss (relative units). 57 [M] never disable zoom. 58 [M] survive user text-spacing overrides (1.4.12). 59 [M] respect OS text-size (Dynamic Type; floor ~16px, never below 12px). 60 [J] don't communicate through fine visual detail only. 61 [M] support high-contrast/forced-colors gracefully.

**9. Contrast & color** — 62 [M] 4.5:1 body / 3:1 large text (incl. over images). 63 [M] 3:1 for UI parts you must see (borders/icons/focus/chart lines). 64 [J] disabled-state exempt but use sparingly. 65 [M] never color as the only information carrier (1.4.1). 66 [M] body links distinguishable by more than color. 67 [J] design for red/green + blue/purple CVD confusions. 68 [M] maintain contrast in both themes + every state (placeholder gray fails most). 69 [J] avoid pure white-on-black for long text (halation).

**10. Motor: targets/pointer/drag/gesture** — 70 [M] targets ≥24px (2.5.8) with 44–48px the real bar; text links exempt. 71 [M] ~8px between adjacent targets. 72 [M] everything draggable achievable without dragging (2.5.7). 73 [M] every multipoint/path gesture has a single-pointer alternative (2.5.1). 74 [M] actions fire on release, cancelable by slip-off (2.5.2). 75 [M] no device-motion-only input; motion actions can be off (2.5.4). 76 [J] no precision demands (no double-click/long-press/hover-only). 77 [J] primary actions in one-handed thumb reach.

**11. Timing** — 78 [M] no un-turn-off-able/adjustable/extendable time limit (2.2.1). 79 [M] anything moving/blinking >5s has pause/stop/hide (2.2.2). 80 [M] session expiry warns + preserves input. 81 [J] success never depends on reaction speed.

**12. Motion & vestibular** — 82 [M] honor `prefers-reduced-motion` app-wide. 83 [M] nothing flashes >3×/second (2.3.1, absolute). 84 [J] avoid large parallax/scroll-hijack/zoom as core nav. 85 [J] animation communicates, ~150–300ms, never blocks input. 86 [M] background video/animation autoplays only if subtle/silent/pausable/reduced-motion-aware.

**13. Deaf & hard-of-hearing** — 87 [M] prerecorded video with speech has accurate captions. 88 [M] live streams have live captions. 89 [M] audio-only = transcript; video = audio description/descriptive transcript. 90 [M] no autoplay sound >3s; audio pausable independently of system volume. 91 [M] every sound cue has a visual equivalent. 92 [J] keep background music below speech. 93 [J] captions on by default when sound is off.

**14. Forms** — 94 [M] every input has a visible, programmatically linked label. 95 [M] placeholder is never the label. 96 [M] instructions/format appear before typing, linked via `aria-describedby`. 97 [M] required fields marked (not color/asterisk alone). 98 [M] `autocomplete` on known-about-the-user fields (1.3.5). 99 [M] right input type + keyboard. 100 [M] group related fields with fieldset/legend. 101 [M] don't auto-advance focus between fields or submit on change (3.2.2). 102 [J] accept human input formats, normalize in code. 103 [J] long forms broken into steps, input preserved.

**15. Errors & tolerance** — 104 [M] failed validation says which field/what's wrong/how to fix, in text (3.3.1/3.3.3). 105 [M] move focus to the error experience on failed submit (`aria-invalid`+`aria-describedby`). 106 [J] error messages polite/specific/jargon-free. 107 [M] legal/financial/destroying actions: review+correct+confirm or undo (3.3.4). 108 [J] prefer undo over confirm. 109 [J] validate on leaving a field/on submit, not per-keystroke.

**16. Cognitive & plain language** — 110 [J] ~9th-grade reading level or below. 111 [J] explain abbreviations/jargon on first use. 112 [M] consistent placement + names for repeated components (3.2.3/3.2.4). 113 [M] help/contact in the same place on every page (3.2.6, new in 2.2). 114 [M] nothing changes context without explicit user action (3.2.1/3.2.2). 115 [J] recognition over recall. 116 [J] one primary task per screen. 117 [J] unambiguous localized human number/date/time formats. 118 [J] don't punish interruption. 119 [J] icons never stand alone for critical nav/actions.

**17. Accessible authentication & redundant entry** — 120 [M] login never depends on a cognitive test/puzzle; allow paste + managers (3.3.8, new in 2.2). 121 [M] never block paste/autofill/managers, esp. auth + OTP. 122 [M] don't ask for the same information twice in one process (3.3.7, new in 2.2). 123 [J] passkeys/biometric/SSO with an accessible fallback for each. 124 [M] OTP: `autocomplete="one-time-code"`, accept full paste, don't split without paste handling.

**18. Touch + AT coexistence** — 125 [M] custom gestures don't collide with screen-reader gestures (visible-control equivalent). 126 [J] work with mobile SR explore-by-touch, not just Tab. 127 [M] use real `click` handlers (AT fires clicks programmatically). 128 [M] don't override/suppress system accessibility settings. 129 [J] test with ≥1 mobile screen-reader flow for mobile-primary products.

**19. Situational/temporary/aging (this is for everyone)** — 130 [J] design accessibility as mainstream (disability is a spectrum everyone visits). 131 [J] sunlight test (usable at half brightness outdoors). 132 [J] one-handed thumb-only covers core flows. 133 [J] aging users get the defaults, not a "senior mode". 134 [J] offer choice of methods, each equal. 135 [J] add value with device capabilities, don't require them. 136 [M] same information + priority order for every input; no stripped "accessible version".

**20. Testing** — 137 [M] automation catches only ~30–40%; never claim accessibility from a clean axe run. 138 [M] run axe in CI, violations = build failures. 139 [M] full keyboard-only pass on every changed flow. 140 [J] screen-reader pass with a real SR per platform class. 141 [M] test at 200%/400% zoom + forced 320px width. 142 [M] verify reduced-motion/dark/forced-colors/largest-text as first-class states. 143 [J] include disabled users in research. 144 [M] maintain an accessibility statement + working feedback channel. 145 [J] accessibility is definition-of-done per ticket, not an audit phase. 146 [J] verify component-library a11y claims on the shipped composition.

## Binding instruction
Before building anything this domain covers, **Read the owning sections of `docs/ux-canon/05-accessibility-inclusive.md` in full.** New surface → read the whole file, and run the §20 manual passes (keyboard, SR, zoom, reduced-motion/forced-colors) — a clean axe run is necessary, never sufficient. Cite principle numbers in code comments and closing reports.
