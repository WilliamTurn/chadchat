# Feedback, states, and system status (canon 03)

Owning file: `docs/ux-canon/03-feedback-states-status.md` (137 principles). **[M]** mechanical, **[J]** judgment. Cite numbers (e.g. `// canon 03 §44`).

## Hard-rule digest

**1. Response-time thresholds** — 1 [M] react to every input <0.1s (result itself is enough). 2 [M] <1s keep flow, subtle state change, no loader. 3 [M] >~1s show a loading indicator. 4 [M] >10s = percent-done + estimate + let them do something else. 5 [M] never flash feedback (delay ~150–300ms, keep ≥300–500ms). 6 [J] optimize perceived time, not just actual; no loading theater over a fixable slow path. 7 [M] render something meaningful first, stream the rest.

**2. Loading indicators** — 8 [M] <~1s: no indicator. 9 [M] ~1–10s unknown: spinner/skeleton. 10 [M] >10s or known length: determinate bar. 11 [M] prefer skeletons over spinners for content regions. 12 [M] skeletons mirror final layout exactly. 13 [J] one skeleton per region, not per atom. 14 [M] skeleton motion subtle/slow or none; respect reduced-motion. 15 [M] localized indicators, not full-screen, when only part loads. 16 [M] one indicator per operation. 17 [M] announce busy state (`aria-busy` + polite live region). 18 [J] never fake progress. 19 [M] on very long waits, say what's happening in words. 20 [M] loading must not trap the user (nav/back/cancel stay live).

**3. Buttons/controls while pending** — 21 [M] pressed state within 100ms, before any round trip. 22 [M] async button keeps its label + adds a spinner (never a bare spinner). 23 [M] disable/guard the trigger to prevent duplicate submission. 24 [M] preserve control dimensions in pending state. 25 [M] show pending on the thing the user touched. 26 [M] pending is a designed state for every interactive control.

**4. Optimistic UI** — 27 [J] optimistic only when success is likely + change is small/local (never payments/irreversible). 28 [M] reconcile with the server response when it arrives. 29 [M] on failure visibly roll back or offer retry — never silently lose the change. 30 [J] don't stack untangleable optimistic writes. 31 [J] never optimistically confirm what the user acts on next.

**5. Success feedback (toasts)** — 32 [J] result visible in place → no toast. 33 [M] confirm actions whose result the user can't see. 34 [M] one toast at a time. 35 [M] auto-dismiss transient toasts ~4–10s. 36 [M] a toast carries at most one action, never a critical one. 37 [M] anything reachable only via a toast is reachable elsewhere too. 38 [M] toasts with an action don't auto-dismiss too fast for AT. 39 [M] toasts never cover the thing being worked on. 40 [M] never put action-needing errors in a transient toast. 41 [M] announce toasts politely (`role="status"`), don't steal focus. 42 [J] one short sentence in product voice. 43 [J] celebration proportional to the achievement.

**6. Error states** — 44 [M] every error answers what/why/what-next. 45 [M] plain language, no codes/jargon/blame. 46 [J] never blame the user. 47 [M] field errors inline, next to the field, persist until fixed. 48 [M] submit failure adds an error summary linking each field, focus moves to it. 49 [M] validate on blur/submit not per-keystroke; re-validate live once in error. 50 [M] never clear input on validation failure. 51 [M] page-level errors get a designed state with a way forward. 52 [J] don't frame ineligibility/permission as a correctable error. 53 [M] every failed network op offers retry (safe/idempotent). 54 [M] auto-retry transient failures with backoff before bothering the user; cap. 55 [M] distinguish your-connection / our-server / your-input. 56 [J] error prevention beats error messages. 57 [J] don't use disabled controls as silent error messages. 58 [M] log/aggregate client errors. 59 [M] an error never blanks the surrounding page (error boundaries). 60 [M] `role="alert"` for blocking errors, polite for advisories.

**7. Empty states** — 61 [M] every list/feed/search/dashboard has a designed empty state. 62 [M] first-use: explain what lives here + primary create CTA. 63 [J] user-cleared: calm good-news, no CTA pressure. 64 [M] no-results: restate query + say nothing matched + ways out. 65 [M] error-empty ≠ empty — never show "nothing here" when the truth is "couldn't load". 66 [M] filtered-to-empty shows active filters + one-tap clear. 67 [J] empty states match the product's visual system. 68 [J] design sparse states (1-item, 2-item), not just 0 and full.

**8. Offline / flaky network** — 69 [M] detect + tell the user they're offline before a failure. 70 [J] offline is a state, not an error. 71 [M] show cached/stale content over nothing, labeled. 72 [M] queue offline writes + sync on return, per-item pending status. 73 [M] tell the user what got queued + confirm sync. 74 [M] never double-apply a queued action (idempotency). 75 [J] design for slow, not just absent (lie-fi). 76 [M] recover automatically on reconnect.

**9. Data freshness & sync** — 77 [J] show last-updated where staleness changes meaning. 78 [M] stale-while-revalidate. 79 [M] pull-to-refresh on mobile feeds / refresh affordance on desktop. 80 [M] background refresh doesn't yank content under the user. 81 [J] on sync conflict never silently discard either side. 82 [M] refetch on focus/reconnect for data others can change.

**10. State persistence** — 83 [M] drafts survive everything (nav/refresh/close/expiry/crash). 84 [M] back returns to what the user saw, incl. scroll. 85 [M] form state survives back-nav + validation failure. 86 [M] persist shareable view state in the URL. 87 [J] restore place across sessions for multi-step/long content. 88 [M] remember UI choices (dismissed banners, sort, collapsed sections).

**11. Interruption / timeouts / autosave** — 89 [M] warn ≥2 min before timeout + extend without losing work. 90 [M] if a session must expire, preserve work across re-auth. 91 [M] autosave long-form input + show status. 92 [M] the "Saved" indicator is truthful (Saving…/Saved/failing). 93 [M] warn before discarding unsaved changes only when there's something to lose. 94 [M] mobile interruption is first-class (return to prior state, timers reconciled).

**12. Real-time & layout stability** — 95 [M] live updates cause no layout shift under pointer/reading position (reserve space). 96 [M] new feed items announce ("N new") not shove. 97 [J] update live values calmly (no blinking). 98 [M] show liveness state (connected/reconnecting) for real-time surfaces. 99 [J] presence/typing indicators accurate and promptly cleared.

**13. Multi-tab / multi-device** — 100 [M] the same account's state converges across tabs/devices. 101 [M] logout/login propagate to all tabs immediately. 102 [M] guard multi-tab edit collisions (version stamps).

**14. Long ops / background work / cancel** — 103 [J] anything past a few seconds runs in the background, frees the UI. 104 [M] background work has visible, findable status. 105 [M] long ops are cancelable where meaningful (say so if not). 106 [M] report partial failure honestly in batch ops. 107 [J] completion notifies proportional to where the user is. 108 [M] multi-step ops show which step.

**15. Confirmations economy** — 109 [J] default to just-do-it + undoable. 110 [J] confirm only destructive+costly+hard-to-reverse. 111 [M] confirm dialog states the specific consequence + names the object; verbs not Yes/No. 112 [M] destructive option visually distinct, never default/primary; Enter must not destroy. 113 [M] catastrophic irreversible = typed confirmation/equivalent friction. 114 [M] undo windows long enough + honest (delay the commit). 115 [M] never chain confirmations.

**16. Badging & unread** — 116 [M] a badge is specific/new/actionable + clears when seen/handled. 117 [M] numeric badges count, dot badges signal new — don't mix; cap ("99+"). 118 [M] unread state per-item, distinct without color alone. 119 [J] never manufacture badge urgency for engagement. 120 [M] badge counts consistent across surfaces.

**17. Haptics & sound** — 121 [J] haptics confirm meaningful moments, not every touch. 122 [M] use the platform's semantic haptic vocabulary consistently. 123 [M] haptics accompany visual feedback, never replace it. 124 [M] UI sounds off by default in productivity; always paired with visuals; honor silent switch. 125 [M] respect system feedback settings (Reduce Motion, haptics off, silent).

**18. Running timers / stopwatches / live sessions** — 126 [M] derive from wall-clock timestamps, never tick counting. 127 [M] on return from background the timer is already correct (incl. completed). 128 [M] countdowns in mm:ss, tabular numerals, zero layout shift. 129 [M] every rest/countdown timer has visible pause/skip/extend, live, no restart. 130 [M] completion signals through every channel at once, sound honoring silent mode. 131 [M] backgrounded completion = scheduled system notification, cancelled if the user returns first (web: keep-awake + correct state on return). 132 [M] keep screen awake during an active session, release the wake lock the moment it ends. 133 [M] an in-progress session is a persistent app-wide state with a return affordance. 134 [M] sessions/timers survive app death (persisted timestamps + resume). 135 [M] stopwatches follow the universal contract (start/stop toggle, lap, reset-when-stopped). 136 [J] auto-started timers announce themselves + are one toggle to disable. 137 [M] announce timer state accessibly + calmly (`role="timer"`, no per-second announcements).
