# Screen recipes and responsive divergence (composition canon 05 + 07)

Owning files: `docs/composition-canon/05-screen-recipes.md` (102 principles), `07-responsive-divergence.md` (57). **[M]** mechanical, **[J]** judgment. Cite ids (e.g. `// comp-canon 05 #13`). Every recipe is a default with stated conditions — deviating is a decision to state out loud, not a drift. Composes UNDER owner decisions, the north star (cardless at ALL widths), and the `app/globals.css` tokens (ds.css port pending — re-point on land). Nav/IA/flows stay ux-canon 02's law; element rules stay ux-canon 04's; containers and gaps stay comp-canon 01/06's.

## Hard-rule digest — canon 05 (screen recipes)

**§1 Recipe grammar (every screen)** — 1 [J] a screen is an ordered stack of zones, one user question each, descending priority — write the question list first. 2 [J] exactly one protagonist zone, named before styling. 3 [M] between-zone space ≥2× within-zone (gap table 06 #8); escalate per the ladder 01 #11. 4 [J] the first phone viewport (~384×~700) contains the answer + primary action; chrome must not eat it. 5 [J] scroll order is priority order — never append. 6 [M] header chrome = orienting title + ≤2 whole-screen actions. 7 [M] phone = one column; desktop = second pane with a defined role or a centered column — never just stretched. 8 [M] primary action in the thumb zone, bottom-anchored. 9 [J] never blend archetypes; two recipes = two screens. 10 [M] every archetype defines where empty/loading/error render: in the content's own zone and position. 10a [M] first-load skeletons top-down in priority order, each mirroring its zone's final rung and rhythm.

**§2 Overview / "today"** — skeleton: whispered context → THE ANSWER → today's plan/action → supporting metrics → extras. 11 [J] top zone answers "what should I do right now?", not "here's all your data". 12 [J] one hero at headline scale; two heroes = zero. 13 [M] NEVER an equal-weight tile grid (the canonical overview defect). 14 [M] greeting/date/branding are whispers. 15 [J] cap at ~3–5 zones, one concept each. 16 [J] every zone pairs state with its one verb, inside the zone. 17 [J] the overview links out, never inlines histories. 18 [J] the surface re-ranks with the day's state (time-aware). 19 [M] desktop: hero stays dominant, max two macro columns, never equal columns. 20 [M] first-run = same skeleton, setup action as hero, labeled frames with teach-copy.

**§3 List/collection** — skeleton: title + count → filter/sort chips → rows grouped under date headers → empty state in rows' position. 21 [M] a row = one primary text + 1–3 metadata + one optional trailing affordance. 22 [J] metadata must differentiate rows; repeated identical values are noise. 23 [J] thumbnails earn their place (recognition) or get cut. 24 [M] group by the users' dimension (date) with editorial headers, not enclosures. 25 [J] group aggregate in the header line — caps for the 1–3-word label ONLY, aggregate in sentence-case mute (Q-DS-4). 26 [J] whitespace first, inset hairlines second, per-row boxes never (default). 27 [M] whole row = one tap target, one destination; one distinct trailing control max. 28 [M] filters as a visible chip row between header and rows; active filters stay visible. 29 [M] constant row-height rhythm within a group. 30 [M] empty state exactly where rows would be: named, why, one action. 31 [J] gallery/grid only when the image IS the content (2-up at phone). 32 [M] desktop: frequently-drilled lists become list-detail; terminal lists stay a centered column. 32a [M] search variant: field between header and filters; query echo + count above rows; no-results ≠ empty (names query, clear-search, clear-filters when filters hide results). 32b [M] selection mode: leading control column + whole-row toggle + full-bleed tint highlight (rung 5) — rows never grow boxes to look selectable.

**§4 Detail** — skeleton: identity (media if identifying → title → classification line) → key-facts band → primary action → body sections by relevance. 33 [M] title dominant, metadata one step down, bound by proximity. 34 [J] lead with media only when it identifies/teaches; never a decorative hero. 35 [M] key-facts band: the 2–4 summary numbers, figures + spaced-caps labels, one row, no boxes. 36 [M] primary action visible without scrolling; pinned when the body is long. 37 [J] body sections descend by what the user came for, each skimmable under an editorial header. 38 [J] in-page tabs only for long AND independently-visited sections. 39 [J] chart before table, latest before oldest in history sections. 40 [M] desktop: media + identity/facts side by side above a single-column body.

**§5 Live-task / logging (mid-workout)** — skeleton: thin pinned status strip → current item dominant → next-up subdued → dominant action pinned bottom. 41 [J] answers exactly three questions at a glance: where am I, what now, what next — everything else comes off. 42 [M] session status = thin pinned strip, always visible. 43 [M] current dominates, done dims, upcoming whispers — three distinct states. 44 [M] one dominant full-width bottom action naming the next thing (Log set → Rest → Next → Finish); never moves. 45 [M] chrome disappears: no tab bar, one visible exit in the strip. 46 [J] density flips to glance: bigger numbers, bigger targets, fewer items. 47 [J] inputs prefilled from last time; logging = one confirm. 48 [M] rest timer = overlay/takeover on the session, never navigation away. 49 [M] actionable elements live in the lower half (one-handed). 50 [M] re-entry restores the live screen exactly. 51 [J] desktop stays a single focused phone-width column; no panes.

**§6 Form/settings** — skeleton: title → grouped rows under spaced-caps headers by frequency → destructive zone isolated last → fine print bottom. 52 [M] topic sections bound by proximity under headers, not boxed panels. 53 [M] a row = label left, current value/control right. 54 [J] order by frequency of use, never alphabet/org chart. 55 [M] one column at every width, left-anchored per 03 #38; never side-by-side fields. 56 [M] instant-apply and batch-save never mix on one screen. 57 [M] destructive actions alone in the final zone, distinct, never adjacent to a safe action. 58 [J] long settings → hub-and-spoke or search, never one endless scroll. 59 [M] version/legal as least-prominent fine print at the absolute bottom. 60 [M] field anatomy is ux-canon 01/02's; this recipe fixes only the skeleton.

**§7 Stats/progress** — skeleton: one time-range control → hero insight + plain-sentence interpretation → supporting chart+context zones by goal relevance → links out. 61 [J] one hero insight, never a wall of charts. 62 [M] every chart ships assembled: question-title + headline number + chart + comparison anchor. 63 [J] numbers first, charts second, tables last (tables live on the drill-in). 64 [M] ONE time-range control governs the whole surface. 65 [J] each zone carries one interpreting sentence. 66 [J] order by the user's stated goal, not data availability. 67 [M] the stats surface links out to per-metric detail screens. 68 [M] insufficient data renders the zone's frame with a stated threshold, never a hidden zone. 69 [M] desktop: supporting zones may pair two-across; the hero never shares its row.

**§8 Chat (AI coach)** — skeleton: minimal header → bottom-anchored stream → suggestion chips → pinned composer. 70 [J] the stream owns the screen; header and composer are thin bands. 71 [M] newest at bottom, opens at latest; auto-scroll only while at bottom; jump-to-latest after scrolling up. 72 [J] user messages = right-aligned bubbles (EARNED container via 01 #41 provenance); coach = left-aligned uncontained editorial text at full measure. 73 [M] message measure ~75–80% width on phones, ~65–75ch centered on desktop. 74 [M] timestamps as grouped whispers at time gaps, never per message; consecutive same-speaker messages group. 75 [M] composer pinned, grows to ~5 lines then scrolls internally; keyboard never covers the last message. 76 [M] suggested replies = one chip row directly above the composer, vanishing on action. 77 [J] structured coach content renders as formatted editorial blocks in the reply flow, never boxes-in-bubbles. 78 [M] new chat = composer + capability intro + 2–4 starter prompts in the stream's position.

**§9 Onboarding / any stepped flow** — skeleton per step: whisper progress → the question as the only headline → large-target options → Continue pinned bottom with Skip. 79 [M] one idea per screen; the headline IS the question. 80 [M] options = large full-width rows or 2-up tiles (earned containers via 01 #39 single-target), unmistakable selection. 81 [M] Continue in the same pinned spot every step, Skip visible near it. 82 [M] progress is a whisper (thin bar or "2 of 5"). 83 [J] value/preview screens alternate with asks, same skeleton. 84 [M] first-run empty = the archetype's own recipe with teach-content in its zones, never a generic screen. 85 [M] decoration never pushes options/Continue below the fold at ~384px. 85a [M] this skeleton binds ANY stepped flow (plan builder, guided setup), compact stepper allowed in the progress slot; split trigger is 03 #41.

**§10 Celebration/completion** — skeleton: Home link top (Q-28) → the verdict headline → 2–4 result numerals → earned recognition only when earned → Back to Workouts bottom (Q-28). 86 [J] a verdict, not a report; composed air; centered composition legitimate. 87 [M] result numerals as one key-facts band; full breakdown lives on the detail screen, linked. 88 [M] records/streaks only when EARNED; gold `--reward` never promised; absent achievement = absent zone. 89 [M] exactly the two decided exits + at most one contextual next step; no rate-us/share-nag/upsell in the way. 90 [M] a celebration collects nothing — inputs happen on the finish step BEFORE it. 91 [J] share affordance = one quiet secondary near the numerals. 92 [J] this is the house milestone skeleton — PRs, streaks, future milestones reuse it.

**§11 Paywall / locked** — skeleton: value statement → selectable tier tiles → selected tier's features → ONE primary CTA → restore + legal fine print. 93 [J] locked features render in place under the approved frost treatment — never vanished, never a bare padlock row. 94 [M] tier tiles = canonical selectable containers (01 #39), identical containment; recommended tier emphasized by hierarchy, never a different containment species. 95 [M] one primary CTA serving the selected tier, plain commitment label, thumb zone, pinned when the list scrolls. 96 [M] phone comparison = stacked tiles or one marked feature list, NEVER a sideways-scrolling matrix. 97 [M] price/period/trial inside the tile; qualifying fine print adjacent to the CTA; nothing price-relevant behind disclosure. 98 [J] house voice and grammar hold: neutral copy, no Chad-voice pressure, no fake scarcity/countdown (banned).

## Hard-rule digest — canon 07 (responsive divergence)

**§A The nine invariants (width may NEVER alter)** — 1 [M] same content at every width; defer behind labeled disclosure, never delete. 2 [J] the phone stack IS the priority ranking; every wider layout preserves that reading order. 3 [M] identical terminology/labels at every width. 4 [M] reflow moves whole groups, never splits them. 5 [M] one visual model, one component set, one token set (cardless at all widths). 6 [M] every interaction reachable at all widths; hover/gesture are accelerators only. 7 [M] source order matches visual order (no `order:` shuffles). 8 [M] crossing a breakpoint never loses state. 9 [J] data meaning invariant; the phone chart may not be vaguer.

**§B Reflow grammar** — 10 [M] single column is the root; width promotes stacked zones to side-by-side, never invents zones. 11 [J] side-by-side only for semantically parallel or supporting zones — never to fill width. 12 [J] reflow at zone level first; zones keep their internal arrangement (container queries). 13 [M] a row of peers wraps as a unit — never one orphan (Switcher). 14 [M] full-width phone buttons become intrinsic-width inline on desktop. 15 [J] list → list-detail for frequently-flipped browse-and-inspect content. 16 [J] hidden-behind-tap on phone → persistent pane on desktop (and the inverse when narrowing — never to nothing). 17 [M] uniform feeds/galleries add columns fluidly (auto-fit + min width); add columns, don't inflate cells. 18 [M] forms single-column at every width, max-width ~400–600, left-anchored per 03 #38; bound short pairs may row. 19 [M] tables reflow deliberately: compare-across-rows → in-container scroll with pinned identity column; record-shaped rows → stacked blocks; tertiary columns → behind detail/expand; decided once per table type. 20 [J] media scales fluidly with preserved aspect; art-direction may recrop, never swap subject. 21 [M] nav reflow (bar↔rail↔drawer, canon 02's) and content layout change at the SAME threshold.

**§C What width buys** — 22 [M] measure cap ~45–75ch always (max-width in ch). 23 [J] width buys MORE CONTENT for scanning/comparing; MARGIN AND MEASURE for reading/one-task — decided per zone. 24 [M] desktop may densify within tokens, never below the 12px floor or target minimums. 25 [J] empty margin is valid; stretched or invented filler content is not. 26 [M] fluid type scales display sizes with clamp floors/caps; body stays ~16–18px everywhere. 27 [M] one page max-width token app-wide; full-bleed reserved for backdrop and shell.

**§D Phone (320–599)** — 28 [M] one dominant column, one alignment spine; centered only for deliberate display moments. 29 [M] text/controls inside `--gutter` (24px min); edge-to-edge earned by media/backdrop/nav only; budget per 02 #13. 30 [J] side-by-side reserved for tightly-bound pairs, tested with long values. 31 [J] first viewport = the surface's answer + primary action. 32 [M] horizontal scroll almost nowhere; a swipe row needs ALL: uniform peers + visible peek + optional browse + reachable elsewhere; auto-rotating carousels rejected. 33 [J] sticky chrome: header + ≤1 bottom element, within the 25% cap (02 #29); prefer collapsing headers. 34 [M] 320px is a valid layout, not survival mode — same composition, tighter margins. 35 [J] long content prioritizes downward with disclosure — never sideways, never hidden.

**§E Desktop** — 36 [J] composed FOR the width, not survived at it (no stretched stack, no crushed half-desktop). 37 [J] a dominant primary region (~2:1) with flanking support; equal halves only for genuine peers. 38 [J] must not decay into a tile dashboard — same separators as phone, the escape hatch no wider. 39 [J] persistent panes only where the phone flow demonstrably ping-pongs; single-focus flows stay single-focus. 40 [M] hover/right-click/fine-pointer unlock nothing exclusive. 41 [J] atmosphere stays continuous horizontally; backdrop full-bleed behind the capped column.

**§F Breakpoint discipline** — 42 [M] fluid-first: correct at EVERY width; breakpoints only change rules. 43 [M] breakpoints live where content breaks, not at device widths. 44 [M] M3 window classes are shared vocabulary + checkpoints, not the only widths. 45 [M] components adapt to their CONTAINER (container queries), the page to the viewport. 46 [J] few breakpoints; >2–3 rule-changing thresholds = over-arranged. 47 [J] design compact and expanded together from one content-priority list — never "port later". 48 [M] one DOM for all widths; no mobile-only/desktop-only twins; no JS width-sniffing for arrangement.

**§G Mechanical reflow checks (every surface)** — 49 [M] zero horizontal page overflow from 320 up, checked continuously. 50 [M] nothing clipped/overlapped/involuntarily truncated at 320–384 with real long values. 51 [M] targets re-verified at the tightest width of every arrangement. 52 [M] no rendered line >~75–80ch anywhere. 53 [J] the priority-order walk: phone stack sequence = desktop reading sequence. 54 [M] the continuous 320→1280 drag: every intermediate state presentable. 55 [M] 400% zoom at 1280 reflows to the single column, nothing lost. 56 [M] house evidence: screenshots 360/390/desktop (+320 when dense), actually inspected. 57 [M] medium widths (~600–840, landscape/split-screen) render a working arrangement.

## Binding instruction
Before building or restructuring any screen, **identify its archetype and Read that recipe section of `docs/composition-canon/05-screen-recipes.md` in full, plus 07's invariants (§A) and the sections your reflow touches**; a screen that seems to need two recipes is two screens. New surface → read both files. Containers, gaps, and headers within the skeleton → load `composition-grouping`; forms/dialog interiors → `composition-forms-overlays`. Reconcile against `app/globals.css` tokens (ds.css port pending — re-point on land) — tokens and owner decisions win. Cite principle ids in code comments and closing reports.
