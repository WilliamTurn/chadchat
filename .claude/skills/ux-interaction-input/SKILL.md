# Interaction and input mechanics (canon 01)

Owning file: `docs/ux-canon/01-interaction-and-input.md` (182 principles). Every rule below is one-line; **[M]** = mechanical (a lint/test could check it), **[J]** = judgment (an auditor must look). Numbers are the canon principle numbers — cite them in code comments, PRs, and closing reports (e.g. `// canon 01 §132`).

## Hard-rule digest

**A. Buttons and controls** — 1 [M] every control has visible default/hover/focus/active/disabled states. 2 [J] looks-clickable ⟺ is-clickable. 3 [M] `<button>` for actions, `<a>` for navigation (never `<div onClick>` to navigate). 4 [J] label the specific action, not OK/Yes. 5 [J] prefer enable-and-validate over disable; if disabled, explain why next to it. 6 [J] a disabled control is never the only way to discover a requirement. 7 [M] async button shows spinner AND keeps its label. 8 [M] keep submit enabled until request starts, then disable to block double-submit (+ idempotent server). 9 [J] one primary action per view; demote the rest. 10 [M] platform-standard primary placement, consistent app-wide. 11 [M] icon-only buttons get accessible name + tooltip. 12 [M] labels opening a follow-up step end with "…". 13 [M] toggle button exposes pressed state (`aria-pressed`) + survives grayscale. 14 [M] respond within ~100ms or show progress; never look dead. 15 [J] never move a control as the user goes to press it.

**B. Forms structure** — 16 [J] ask only what you need, when you need it. 17 [M] single-column layout. 18 [J] order fields as users think; group with fieldset/legend. 19 [M] mark required vs optional explicitly (mark the minority). 20 [J] field width matches expected input length. 21 [J] never re-ask data the system knows. 22 [M] warn before navigation discards unsaved changes. 23 [M] preserve input across errors/refresh/back. 24 [M] Enter submits from a text input; textareas use Cmd/Ctrl+Enter (chat composers are the scoped exception — canon 07 §C.23). 25 [M] hydration must not eat focus or typed chars. 26 [J] allow submitting an incomplete form to surface all errors at once.

**C. Labels and placeholders** — 27 [M] visible persistent label outside the field (placeholder is never the label). 28 [M] label programmatically tied to control (`for`/`id`). 29 [M] labels top-aligned. 30 [J] placeholders show format examples, not instructions. 31 [M] hint text sits between label and input, up front. 32 [J] human labels, no DB/jargon names.

**D. Input types, keyboards, autofill** — 33 [M] correct `type`/`inputmode` per field. 34 [M] standard `autocomplete` tokens on identity/address/payment fields. 35 [M] never block paste/autofill/password-managers, incl. OTP (`autocomplete="one-time-code"`). 36 [M] disable autocorrect/autocap/spellcheck on email/username/code. 37 [M] `type=number` only for true quantities; codes use `inputmode=numeric`+pattern. 38 [J] steppers only for small adjustments; always allow tap-to-type. 39 [M] mobile input font-size ≥16px (no iOS zoom). 40 [J] autofocus the one primary input on desktop; rarely on mobile.

**E. Validation** — 41 [M] validate on blur or submit, never per-keystroke before finishing. 42 [M] once a field erred, re-validate every keystroke so the error clears instantly. 43 [M] errors inline, adjacent to the field. 44 [M] on submit: error summary + focus first error + link each item to its field. 45 [J] say what's wrong AND how to fix, plainly; never blame. 46 [M] error state is more than color (icon+text, `aria-invalid`/`aria-describedby`). 47 [M] accept free-format input and normalize it. 48 [J] don't block typing to enforce format. 49 [J] positive/valid confirmation only where it helps. 50 [M] never clear the whole form or the erred field on failure. 51 [J] server errors map back to per-field inline messages.

**F. Specific entry types** — 52 [J] known dates (birthdays): 3 labeled fields or one text field, never a calendar. 53 [M] calendar pickers always allow typed entry + keyboard. 54 [J] phone = one field, accept any punctuation. 55 [M] address = autocomplete + always a manual fallback. 56 [M] card number = single field, auto-space 4s, auto-detect brand. 57 [M] expiry MM/YY, CVV help affordance. 58 [J] email = no confirm-field double entry; suggest typo fixes. 59 [M] password creation = rules up front, live-check, show/hide. 60 [M] login password = one field, show/hide, paste, `autocomplete="current-password"`. 61 [M] numeric fields preselect content on focus.

**G. Multi-step forms** — 62 [J] steps of related questions; one thing per page on mobile-heavy flows. 63 [M] step indicator with position + total. 64 [M] Back always works and never loses data (app + browser). 65 [J] review/summary step with per-item "Change" links on consequential flows. 66 [J] save progress on long flows. 67 [J] branch, don't show irrelevant questions.

**H. Selection controls** — 68 [J] radios for 2–5 exclusive visible options. 69 [J] checkboxes for zero-or-more / opt-ins taking effect on save. 70 [J] switches only for instant-effect binary state (no Save). 71 [J] toggle label names the thing, not the state. 72 [J] radios get a default or explicit "none". 73 [J] dropdowns are a last resort (>5–7 options, no comparison). 74 [J] long lists get a searchable combobox. 75 [J] segmented controls for 2–5 always-visible view/filter options. 76 [J] sliders only for approximate values, paired with a numeric field. 77 [J] steppers for small-range adjustments. 78 [J] native mobile pickers beat custom dropdowns on touch. 79 [J] preselect safe defaults; never preselect consequential/consent choices.

**I. Commit models** — 80 [J] one commit model per surface, legible: all-instant or nothing-until-Save. 81 [J] settings apply instantly with feedback; documents autosave-with-status or explicit save. 82 [M] explicit-save surfaces track dirtiness with discard protection. 83 [J] instant-apply destructive changes get undo, not confirm. 84 [M] Cancel/Discard genuinely reverts (atomic).

**J. Keyboard and focus** — 85 [M] everything pointer-operable is keyboard-operable, no traps. 86 [M] focus always visible (`:focus-visible`), never suppressed without replacement, never fully obscured. 87 [M] tab order = visual/reading order (no positive `tabindex`). 88 [M] Tab between widgets, arrows within composite widgets (roving tabindex). 89 [M] manage focus on open/close/delete (dialog in→return; delete→neighbor). 90 [M] Esc closes the topmost transient surface only. 91 [M] standard editing keys work everywhere text is edited. 92 [J] never hijack browser/OS shortcuts.

**K. Per-widget ARIA contracts (all [M], §93–111)** — dialog(93)/alertdialog(94)/menu(95)/tabs(96)/listbox(97)/combobox(98)/slider(99)/spinbutton(100)/switch(101)/checkbox(102)/radio-group(103)/disclosure(104)/accordion(105)/tree(106)/grid(107)/toolbar(108)/tooltip(109)/carousel(110)/splitter(111) each has an exact key/focus contract — read §K before hand-building any of them; prefer the Radix primitive that already implements it.

**L. Touch mechanics** — 112 [M] targets ≥44×44pt / 48dp (web floor 24px, ≥44 preferred); expand hit area if glyph is smaller. 113 [M] label+control share one hit target. 114 [J] primary actions in the thumb zone, destructive out of it. 115 [M] every gesture has a visible alternative (WCAG 2.5.1). 116 [J] platform-standard gestures only. 117 [M] fire on touch-release, not touch-down. 118 [J] don't let scrolling trigger taps. 119 [M] keep clear of OS back-gesture edge zones. 120 [M] never disable zoom. 121 [M] `overscroll-behavior: contain` on modals/drawers. 122 [M] focused field never under the keyboard.

**M. Drag / swipe / long-press** — 123 [M] drag always has an explicit non-drag alternative (WCAG 2.5.7). 124 [J] draggables signal draggability; drop targets highlight. 125 [M] during drag: disable text-select, inert dragged el, auto-scroll edges, animate drop. 126 [M] drag is cancelable (Esc / drop-outside reverts). 127 [J] platform swipe idiom; destructive full-swipe still gets undo/confirm. 128 [J] long-press is never the only path to a primary action. 129 [J] reorder via drag handles + a keyboard/menu alternative.

**N. Destructive actions** — 130 [J] prefer undo over confirm for frequent reversible actions. 131 [J] reserve confirm for rare/irreversible/high-stakes; state the specific consequence. 132 [M] confirm buttons repeat the verb (never Yes/No/OK); destructive styled + NOT default focus. 133 [J] catastrophic scope gets proportional friction (type-to-confirm/re-auth). 134 [M] separate destructive controls spatially; in menus last, after a divider, in destructive color. 135 [J] soft-delete/trash by default where domain allows. 136 [J] relabel when "Cancel" is itself destructive ("Cancel order"/"Keep order").

**O. Text input specifics** — 137 [M] masks auto-format but never block/reorder/fight paste; store raw. 138 [M] character counters near the limit, announced, never hard-stop silently. 139 [M] textareas auto-grow to a max then scroll. 140 [J] show all constraints before violation. 141 [M] don't break IME/dictation with keystroke interception.

**P. Shortcuts** — 142 [J] shortcuts for frequent power actions, platform-standard set. 143 [J] discoverable (menus/tooltips + command palette). 144 [M] single-letter shortcuts never fire in text fields; remappable/disableable (WCAG 2.1.4). 145 [M] every shortcut action also exists as a visible control.

**Q. Multi-select / bulk** — 146 [M] entering multi-select is explicit; contextual action bar shows "N selected". 147 [J] select-all/clear-all + always-visible count, explicit scope. 148 [M] desktop selection honors click/Shift/Ctrl conventions; checkbox rows are the touch-safe alt. 149 [J] bulk actions confirm scope in the verb ("Delete 12 items") + report partial failures. 150 [J] selection survives sort/filter visibly or is cleared with notice.

**R. Search-as-you-type** — 151 [M] debounce ~150–300ms, never block typing, guard races. 152 [M] highlight matches, 5–10 suggestions, keyboard-navigable (combobox §98). 153 [J] recents/suggestions on focus; tolerate typos. 154 [M] Enter runs the full literal search. 155 [M] announce result counts (`aria-live`) + useful no-results recovery. 156 [M] filter/search state is URL-reflected where shareable.

**S. Time and duration** — 157 [M] duration uses a dedicated mm:ss pattern echoed back in words. 158 [M] time-of-day offers picker + typed entry, honors 12/24h; AM/PM is a toggle. 159 [J] common durations get one-tap presets; arbitrary stays typeable. 160 [M] duration/time fields summon numeric keyboards, accept paste. 161 [J] ask at the precision the task needs. 162 [M] one duration format per quantity app-wide, tabular numerals.163 [M] relative time entry shows the resolved absolute result before commit.

**T. Recurrence** — 164 [M] calendar-app convention (presets first, custom behind), echoed as plain English. 165 [M] day-of-week = always-visible toggle chips. 166 [M] every recurrence has a visible end condition. 167 [M] editing/deleting a recurring item asks scope (this / this-and-following / all).

**U. Names, addresses, units** — 168 [M] prefer one full-name field; no first/last assumptions. 169 [M] address forms adapt to the country (chosen first). 170 [M] unit preference (kg/lb) is a first-class setting applied everywhere; store canonically. 171 [M] locale governs calendar/week-start with an override.

**V. Editing surfaces** — 172 [M] editor-class surfaces get real multilevel undo/redo with platform bindings. 173 [J] undo units match user intent. 174 [J] undoable set is consistent; selection/view changes don't consume undo. 175 [M] undo/redo are visible toolbar controls with honest disabled states. 176 [J] documents get version history with restore. 177 [M] canvas follows the universal pan/zoom contract. 178 [M] on-canvas selection follows desktop conventions.

**W. Repeat accelerators** — 179 [M] frequent repeated entries get "repeat last"/"copy previous" (prefilled, editable). 180 [M] Duplicate is first-class on any user-built object. 181 [J] once history exists, creation leads with recents/templates. 182 [J] ghost carried-over values as suggestions, not fresh entries.
