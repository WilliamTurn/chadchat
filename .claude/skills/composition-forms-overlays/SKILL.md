# Forms, overlays, and placement grammar (composition canon 03 + 04 + 08)

Owning files: `docs/composition-canon/03-forms-input.md` (52 principles), `04-dialogs-sheets-overlays.md` (48), `08-placement-grammar.md` (62). **[M]** mechanical, **[J]** judgment. Cite ids (e.g. `// comp-canon 04 #22`). Input BEHAVIOR (validation timing, keyboards, commit models) is ux-canon 01's law; container SELECTION (dialog vs sheet vs page) is ux-canon 02 §17's; these files own geometry, interior anatomy, and position. The meta-rule of 08: **an element kind has exactly one home, and it lives there on every screen.** Composes UNDER owner decisions, the north star, and the `app/globals.css` tokens (ds.css port pending — re-point on land). The motivating defect for 04 is the real finish-workout dialog screenshot — clipped unit label, horizontal scrollbar in a dialog, nested card beside a flat sibling, buried confirm buttons.

## Hard-rule digest — canon 03 (form geometry)

**§A Labels** — 1 [M] top-aligned labels, label and field on one left edge (the default at every width). 2 [J] side labels only on dense desktop-only scan surfaces; restack below tablet. 3 [M] side labels, if ever, right-align toward the field. 4 [M] the inside of the field is never the label's home; visible label outside the border always (floating labels contested — owner decision required). 5 [M] label sits ≤ half as far from its own field as from the next block (4–8px vs 20–32px). 6 [J] labels are one short line; a second sentence is help text. 7 [M] checkboxes/radios reverse: control left, label right, aligned to the label's FIRST line. 8 [M] label + help + input form one tap target with no dead gap.

**§B Width as affordance** — 9 [J] field width signals expected answer length. 10 [M] known-length answers get fixed ch-sized widths (2–4ch minutes, 4–5ch year). 11 [M] unknown-length answers cap at ~320–480px, never full-bleed on wide screens. 12 [J] uniform-full-width-everything is a desktop defect; on phones variable-length may fill, fixed short fields stay short. 13 [M] no field ever exceeds its container's content box (`max-width:100%`) — the dialog-scrollbar failure. 14 [M] same expected answer = same width everywhere; width classes live in tokens. 15 [M] short fields still fit content + caret + browser-injected icons.

**§C Multi-field rows and units** — 16 [M] one field per row default; share only when the fields are one answer in the user's head (day/month/year, min/s). 17 [M] a shared row is a labeled group: one group label + small per-part labels (GOV.UK date geometry). 18 [M] design the row at 320px FIRST: fixed widths + gaps + units must fit the narrowest container it will ever live in — never clips, never scrolls. 19 [M] units attach as prefix/suffix inside the field's connected construct via the shared affix slot — never loose wrapping text (the "0 min 0 s" failure). 20 [M] affixes match field height, vertically centered, never look pressable. 21 [M] input boxes in a row align on one axis even when labels wrap. 22 [M] within-row gaps < between-row gaps. 23 [J] short fixed-field rows never restack at phone widths (they fit by design); only variable-width rows stack. 24 [M] date entry = three content-sized boxes (2/2/4ch), visibly one group. 25 [M] field + stepper/adornment = one visual unit with a single outer boundary.

**§D Help/placeholder/error slots** — 26 [M] fixed slot order on every field: label → hint → input → error/counter (GOV.UK slot, standing house default via ux-canon 01 #31). 27 [M] type-changing help sits BEFORE the input; afterthoughts (counters) after. 28 [M] errors appear in one fixed slot adjacent to the field, same slot app-wide. 29 [M] RESERVE SPACE for error/supporting text, system-wide (owner-resolved 2026-07-23: "nothing ever jumps"); never horizontal shifts, overlays, or caret displacement. 30 [M] error/help text wraps within its field's own column, never widening the row. 31 [M] error marks the field itself (border/accent) plus icon + text from semantic tokens. 32 [M] placeholder visibly lighter than a filled value, never confusable. 33 [M] counters in the after-slot, only on real limits. 34 [M] help ⓘ attaches to the label line, never inside the input box.

**§E Section structure** — 35 [M] one column; the fill-in path is a single straight line down one left edge (§C rows are the only exceptions). 36 [J] group with whitespace first; headings only for nameable topics, never boxes per group. 37 [M] three-tier rhythm from tokens: within-row < between-blocks < between-sections; heading binds to what follows. 38 [M] the form is a ~400–600px max-width column, left-anchored to the page's content edge (THE canonical form-column rule; centered only in centered compositions). 39 [M] radio/checkbox groups get field-label geometry: group label + options indented to one edge. 40 [M] form and wizard actions anchor to the form's LEFT content edge, primary first, never varying (dialog pairs follow 04 §28's trailing convention instead — one convention per context). 41 [J] a form longer than ~3 phone screens splits into steps. 42 [M] conditional fields appear directly below their trigger, connected, pushing down only.

**§F Required marking** — 43 [M] mark the minority, in text, appended to the label line ("(optional)"). 44 [M] if asterisks: after the label + a key at top; ONE convention app-wide.

**§G One input system** — 45 [M] exactly one text-input component; every field an instance — same height, padding, border, radius, slots, focus; only width and type-affordances vary (input tokens = DS gap flagged for the port session; this rule is their spec). 46 [M] all row-sharing controls share one exact control-height token. 47 [M] selects/comboboxes/pickers wear the same box, differing only by affordance icon. 48 [M] one focus treatment everywhere, 3:1 contrast. 49 [M] every field meets touch floors (≥44–48px tall) — a 2ch field is narrow, not short. 50 [M] value text ≥16px on mobile, one size token app-wide. 51 [M] the full state inventory renders identically on every field. 52 [M] dialogs and sheets use the SAME input system — no "dialog-sized" variants (the duration-field failure's origin).

## Hard-rule digest — canon 04 (overlay internal anatomy)

**§1 Anatomy contract** — 1 [M] every overlay = title → supporting content → actions, in that order. 2 [M] title first, largest, wraps — never truncates; top-trailing corner reserved for close. 3 [J] one alignment axis for the whole overlay: content overlays start-aligned; centered only for the short alert form. 4 [J] one title; interior headings at title scale = overflow signal. 5 [M] zone gaps > intra-zone gaps (squint-separable). 6 [J] body answers the title immediately: title + first line = the whole decision. 7 [M] a leading icon switches to the centered alert form; never decoration beside a left title. 8 [M] close X top corner, ≥44px target, no title collision. 9 [J] nothing else in the title zone — tabs/steppers inside an overlay mean it outgrew the container.

**§2 Content budget** — 10 [M] a confirm's CEILING: one title + 1–3 sentences + at most one simple input + 2–3 actions. 11 [M] overflow signals — ANY ONE means wrong container (escalate alert → dialog → sheet/full-screen → page): body scrolls at 320–384; ≥2 input groups; any interior section needing its own heading/box; multi-step or branching; needs the page beneath as reference. 12 [J] a confirmation is a decision surface, not data collection — fields wanting collecting = a finish STEP, not a grown confirm (one exception: typed-confirmation for destructive). 13 [J] every element serves the single decision; a second decision nested inside = a step. 14 [J] optional content in a sheet defaults collapsed/below the smallest detent. 15 [M] NEVER shrink type/spacing/labels to fit — same scale as the page; doesn't fit = wrong container.

**§3 Interior containers** — 16 [M] the overlay IS the container; content sits directly on its surface. 17 [J] interior separation: spacing → subtle divider → contrast band → box, weakest that works. 18 [J] a nested card inside an overlay is a defect signal. 19 [J] defensible interiors depict a THING (code block, input, media preview, object-being-acted-on) — organization boxes are the defect. 20 [M] never mix boxed and unboxed sibling groups (the screenshot failure). 21 [M] checkbox/toggle options = plain full-width list rows, no enclosing card.

**§4 Scroll rules** — 22 [M] horizontal scroll inside an overlay is ALWAYS a defect, zero exceptions. 23 [M] only the body zone scrolls; title pinned above, actions pinned below. 24 [M] actions never scroll out of reach at any width/scroll/keyboard state (automatable: action bar bottom ≤ visual viewport bottom). 25 [M] scrolling bodies show a boundary cue (hairline/shadow) only while content is clipped. 26 [M] page behind locks; `overscroll-behavior: contain`; scroll restored on close. 27 [M] centered dialogs cap ~80–85% viewport height; only sheets/full-screens touch edges.

**§5 Action bar** — 28 [M] inline pairs trail-align: primary outermost-right, Cancel before it. 29 [M] two actions the norm, three the ceiling (third separated at the leading edge or stack). 30 [M] stack full-width when labels would wrap/truncate/crowd; a label never wraps or ellipsizes. Stacked order: PRIMARY ON TOP, Cancel at the very bottom (owner-resolved 2026-07-23, Apple style, system-wide). 31 [M] sheets/full-screens: actions in the top bar OR a pinned bottom bar — one pattern app-wide, never both, never floating mid-content. 32 [M] destructive primaries keep the primary position with danger styling + extra separation when stacked; never auto-focused. 33 [M] one height/baseline/size token per bar; emphasis by fill, not geometry. 34 [M] bar padding matches content padding; bottom bars clear `env(safe-area-inset-bottom)`. 35 [J] buttons inset within the padded bar (Carbon full-bleed rejected as house law).

**§6 Sheets** — 36 [M] grabber iff drag-resizable/dismissible; a true bottom sheet is draggable by contract — a fixed bottom surface is not a sheet and gets no grabber. 37 [J] design for the smallest detent first: essentials visible at medium without scrolling. 38 [M] top corners rounded (token), bottom flush, ~24px grabber zone padding. 39 [M] sheet headers sticky while content scrolls at full detent. 40 [M] keyboard avoidance is the sheet's job: focused field AND primary action stay visible above the keyboard (verify with `visualViewport`); inputs ≥16px. 41 [M] inner scroll only at full expansion; below that, drag expands; scroll container = drag surface. 42 [M] wide viewports cap sheets ~640px, centered/side-anchored — never full-width.

**§7 Sizing per breakpoint** — 43 [M] phone dialogs = viewport minus 16–24px insets per side; every interior element fits the 320px content box. 44 [M] desktop caps: ~400px confirms, ~560–640px content dialogs; never percentage-of-screen. 45 [M] one interior padding token set, constant — padding never shrinks to buy room. 46 [M] every multi-element row wrap-tolerant at the 320px content box; unit width budgeted with its field; fixed short rows (03 #18/#23) fit by design and never stack. 47 [M] phone max-height ~80% of the VISUAL viewport (keyboard-aware); hitting the cap on desktop = escalate. 48 [M] popovers ≤ ~360px, never scroll in either axis.

## Hard-rule digest — canon 08 (placement grammar)

**§A Reading gravity** — 1 [M] every zone starts top-left with what identifies it. 2 [J] top = identity/answer, middle = evidence, bottom = commitment; never invert. 3 [J] design against the F-pattern: front-load left edges; right-of-center is invisible. 4 [J] sparse screens read in a Z; forward = bottom/right, retreat = left/top, never swapped. 5 [J] the first viewport carries identity + the answer, not decoration. 6 [M] chrome at the edges, content in the middle, neither invades. 7 [M] an action never sits above the thing it commits. 7a [M] RTL mirrors every directional rule wholesale, all-or-nothing.

**§B Primary action** — 8 [M] lives at the bottom of its flow's content — after everything it commits. 9 [J] pin to the bottom edge only when valid the whole time ("could the user legitimately press this before scrolling?"). 10 [M] pinned bars clear safe areas and add their height as scroll padding. 11 [M] pinned vs in-flow decided once per archetype; siblings match. 12 [M] desktop page-level primary may live top-trailing in the page header (whole-page actions only); collapses to bottom-of-flow on phones. 13 [M] dialog/overlay/inline-confirm pairs: primary trailing (right) — forms and wizard footers are 03 #40's left-anchored territory instead. 14 [M] vertical stacks: primary on top (safe action may take top when primary is destructive). 15 [M] a primary never floats mid-screen between zones. 16 [J] one home per action; the only repeat: top + bottom of a long page, never co-visible.

**§C Secondary/destructive** — 17 [M] secondary sits immediately adjacent to the primary, before it in reading order. 18 [M] tertiary retreats into the overflow menu at the trailing edge; destructive last, separated. 19 [J] destructive never where the reflex tap lands. 20 [M] back/cancel at the leading edge; a lone bottom-pinned cancel lies about being primary. 21 [M] zone actions in the zone header's trailing slot; item actions on the item's trailing edge — scope = which container's edge.

**§D Icon-only vs labeled** — 22 [M] icon-only = chrome-edge citizens; content actions get text labels. 23 [M] top-bar grammar: back leading, title leading-or-center, ≤2–3 trailing tools then overflow. 24 [M] global nav: bottom on phones, top/leading on desktop, never both, never in content. 25 [J] FAB: bottom-trailing, one max, needs owner approval (north star rarely wants one).

**§E Metadata** — 26 [M] identity first, metadata after/below in diminished style — never before. 27 [M] THE house row: leading identity visual → title over supporting text → trailing meta/affordance; never rearranged per screen. 28 [M] only an overline may sit above a title. 29 [J] timestamps: one position per list archetype (trailing message-style OR inline-below feed-style), never mixed. 30 [M] counts/badges attach to what they count (badge top-trailing on icon). 31 [M] status: presence on the identity (dot), workflow state in the trailing/meta slot — never swapped. 32 [M] detail pages open overline → title → one metadata line → actions; body after. 33 [M] value dominant, label in one fixed slot (above or below), chosen once app-wide.

**§F Helper text** — 34 [M] explanations attach directly below the thing explained, inside its group. 35 [M] helper text never floats between unrelated elements. 36 [M] zone-level explanation under the zone heading, once. 37 [J] sometimes-needed help = ⓘ trailing its subject's LABEL (not the row edge); must-know stays inline. 38 [M] qualifying fine print sits between content and the action it qualifies.

**§G Icons, media, drag** — 39 [M] leading icon = what this is; trailing icon = what happens. 40 [M] chevron-right = navigates, chevron-down = expands; each means nothing else; no chevron for neither. 41 [M] buttons: leading icon reinforces the verb; trailing = direction/menu; never both sides. 42 [M] badge top-trailing, presence dot bottom-trailing — fixed corners. 43 [M] external links declare with trailing ↗. 44 [M] icon belongs to its text: same line, optically centered, one gap token. 44a [M] media takes one tokenized aspect ratio per component context; caption below in the media's group; a framing radiused block is a container (01 §4 tests); grid gutters = `--sp-4`. 44b [M] reorder grammar: handle at the trailing edge, drop shown as a parting gap, one labeled mode entry/exit in the zone header; no handle on non-reorderable rows.

**§H Alignment** — 45 [M] text left-aligns; centering only for short display content. 46 [M] compared numbers right-align on a shared edge, tabular figures. 47 [M] one strong content edge per zone; same-kind elements share it EXACTLY (off-by-a-few-px = broken). 48 [J] split label-left/value-right only in bounded narrow rows; wide containers keep label+value adjacent left. 49 [M] a centered composition centers everything on one axis — no strays. 50 [M] inline lockups baseline-align; value+unit non-breaking, never wrapped apart.

**§I Repetition rule** — 51 [M] an element kind recurs in the identical slot everywhere. 52 [M] placement lives in the shared component, never per-screen CSS. 53 [J] a new element kind gets ONE recorded placement decision, then inherited. 54 [J] never fix local crowding by moving an element out of its slot — fix density/truncation or change ALL instances.

**§J Interjections and pinned chrome** — 55 [M] page banners: one slot, directly below the top bar, above ALL content including filters; persisting conditions pin, informational scroll away; max two deep. 56 [M] toasts anchor bottom-center ABOVE the topmost pinned edge (tab bar, pinned CTA, keyboard), clearing safe areas, never covering controls. 57 [M] one transient at a time; a toast never renders over a modal scrim — modal feedback renders inside the modal or after close. 58 [M] pinned elements meet in fixed order and displace, never overlap (top: bar → pinned header → filter row; bottom: tab bar → pinned CTA → toast), each adding scroll padding; combined budget = 02 #29's 25% cap. 59 [M] bulk-select transforms the top bar in place (Cancel leading, count as title, actions trailing → bottom bar when they outgrow it); the leading control shifts ALL rows together; mode entry/exit never scrolls the list.

## Binding instruction
Before building or changing any form, field, overlay interior, or element placement, **Read the owning sections of the three files in full**. Any dialog/sheet content: check 04 #11's overflow signals FIRST — if one fires, escalate the container (ux-canon 02 §17), don't restyle. Any field: it is an instance of the one input system (03 #45–52), rows designed at 320px (03 #18). Any element: it has exactly one home (08 #51–54). New surface → read all three. Containers and gaps around the form → load `composition-grouping`; the screen's skeleton → `composition-screens`. Reconcile against `app/globals.css` tokens (ds.css port pending — re-point on land) — tokens and owner decisions win. Cite principle ids in code comments and closing reports.
